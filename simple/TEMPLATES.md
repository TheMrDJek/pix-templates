# 🔄 Простые шаблоны PIX RPA

## 📋 Введение

Простые шаблоны PIX RPA представляют собой легковесные решения для автоматизации бизнес-процессов с линейной логикой выполнения. В отличие от транзакционных шаблонов, они используют упрощенную модель из трех состояний (Init → Processing → End), что делает их идеальными для процессов с последовательным выполнением шагов без необходимости управления отдельными транзакциями.

## ✨ Ключевые особенности

- **3 состояния** машины состояний: Init, Processing, End
- **Линейное выполнение** процесса без обработки транзакций
- **Легкая настройка** и быстрое внедрение
- **Минимальные требования** к ресурсам
- **Гибкая система уведомлений** через различные каналы

## 🔄 Структура машины состояний

Простые шаблоны используют машину состояний с тремя основными этапами:

### 1. Init State (Инициализация)
- Загрузка конфигурации
- Проверка доступности ресурсов
- Подготовка соединений и логирования

### 2. Processing State (Обработка)
- Выполнение основной бизнес-логики
- Обработка данных
- Управление ошибками

### 3. End State (Завершение)
- Освобождение ресурсов
- Формирование отчетов
- Отправка уведомлений

## ⚙️ Настройка шаблонов

### Управление ассетами по окружениям

Простые шаблоны поддерживают динамическое переключение между окружениями разработки, тестирования и промышленной эксплуатации через входной параметр `Environment`.

**Принцип работы:**
1. При инициализации конфигурации робот проверяет значение входного параметра `Environment`
2. Если параметр заполнен, робот ищет в мастере (оркестраторе) ассеты с соответствующим суффиксом окружения:
   - `_dev` - ассеты для среды разработки
   - `_test` - ассеты для тестовой среды
   - `_prod` - ассеты для промышленной среды
3. Если параметр `Environment` оставлен пустым, робот использует ассеты без суффиксов

**Процесс использования ассетов с суффиксами:**
```
# В состоянии Init робот выполняет следующий алгоритм:

1. Проверяет наличие входного параметра Environment
2. Если параметр задан (например, "test"), формирует суффикс "_test"
3. При обращении к ассету "ConnectionString" робот сначала пытается получить "ConnectionString_test"
4. Если ассет с суффиксом не найден, робот попытается получить "ConnectionString" без суффикса
```

**Пример использования:**
```
# Запуск робота с параметром
Environment = "test"

# Ассеты в оркестраторе:
ConnectionString_dev = "Server=dev-db;Database=DevDb;User Id=dev_user;Password=****;"
ConnectionString_test = "Server=test-db;Database=TestDb;User Id=test_user;Password=****;"
ConnectionString_prod = "Server=prod-db;Database=ProdDb;User Id=prod_user;Password=****;"

# При инициализации конфигурации робот:
1. Определяет значение Environment как "test"
2. Формирует суффикс "_test"
3. При запросе ассета "ConnectionString" сначала ищет "ConnectionString_test"
4. Находит ассет "ConnectionString_test" и использует его значение для подключения к БД
5. В результате робот подключается к тестовой БД, а не к продакшн
```

**Когда это особенно важно:**
- Когда для разных сред (разработка, тестирование, продакшн) используется один и тот же экземпляр мастера
- Для обеспечения повышенной безопасности и разграничения доступа к критичным ресурсам
- При работе с чувствительными данными, требующими строгого разделения между средами

**Преимущества подхода:**
- Единый исходный код для всех окружений
- Централизованное хранение чувствительных данных в оркестраторе
- Быстрое переключение между окружениями без перенастройки
- Предотвращение случайного использования продакшн-данных в тестовой среде
- Возможность запуска робота с разными настройками без изменения кода

> 💡 **Рекомендация:** Используйте стандартизированные суффиксы `_dev`, `_test` и `_prod` для всех ассетов, требующих разных значений в различных окружениях. Храните в ассетах с суффиксами все параметры, которые различаются между средами: URL-адреса, пути к файлам, учетные данные и т.д. Если не требуется использование суффиксов, оставьте параметр Environment пустым.

### Формат конфигурации

Конфигурация в шаблонах хранится в формате `Dictionary<string, string>`, так как оркестратор (мастер) возвращает значения ассетов только в виде строк. При необходимости использования других типов данных выполняется преобразование типов в коде.

```csharp
// Получение строкового значения
string filePath = config["FilePath"];

// Преобразование в числовой тип
int retryCount = int.Parse(config["RetryCount"]);

// Преобразование в логический тип
bool isArchiveEnabled = bool.Parse(config["ArchiveEnabled"]);

// Преобразование в DateTime
DateTime processingDate = DateTime.Parse(config["ProcessingDate"]);

// Пример использования в фильтре файлов
string filePattern = config["FilePattern"];
var files = Directory.GetFiles(filePath, filePattern);
```

### Работа с учетными записями

Для работы с учетными данными (логины, пароли) в шаблонах используется особый подход:
1. В конфигурации хранится только название ассета с учетной записью
2. При необходимости использования учетной записи применяется скрипт `GetCredentials`
3. Скрипт возвращает объект, содержащий логин и пароль

**Пример работы с учетными записями для отправки почты:**
```csharp
// Ассет в конфигурации
// SmtpCredentials = "CompanySmtpCredentials"

// В коде робота
var emailCredentials = GetCredentials(config["SmtpCredentials"]);
string emailUser = emailCredentials.Username;
string emailPassword = emailCredentials.Password;

// Пример отправки email
using (SmtpClient client = new SmtpClient(config["SmtpServer"]))
{
    client.Port = int.Parse(config["SmtpPort"]);
    client.EnableSsl = bool.Parse(config["SmtpEnableSsl"]);
    client.Credentials = new NetworkCredential(emailUser, emailPassword);
    
    MailMessage message = new MailMessage();
    message.From = new MailAddress(emailUser);
    message.To.Add(config["AdminEmails"]);
    message.Subject = $"Результаты обработки {DateTime.Now:yyyy-MM-dd}";
    message.Body = $"Обработано файлов: {processedFiles}\nОшибок: {errorCount}";
    
    client.Send(message);
}
```

Такой подход обеспечивает:
- Безопасное хранение учетных данных в зашифрованном виде в оркестраторе
- Отсутствие паролей в коде или конфигурационных файлах
- Централизованное управление учетными данными
- Возможность изменения учетных данных без изменения кода робота
